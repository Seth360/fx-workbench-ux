# AI工作台UX规范变更记录

所有规范反馈必须记录在此，防止同类问题在新卡片或其他 AI 工具中重复出现。

## 1.5.7 - 2026-09-04

- 现象：设置底部“保存配置”会另存包含页签顶栏、设置抽屉和 CRM 导航的完整编辑器页面；旁边“导出”只下载配置 JSON，无法得到可独立交付的单工作区 HTML。
- 根因：旧运行时把整页源代码持久化与配置 JSON 导出拆成两个动作，没有把顶层页签定义为独立页面的导出边界，也没有按页签名生成文件。
- 强制规则：设置底部只保留“导出页面 / 重置”。导出必须遍历所有顶层页签，为每个页签生成以当前可见页签文案命名的自包含 HTML；每份文件只包含该页签的主画板，禁止包含页签顶栏、设置抽屉、CRM 导航、其他页签、编辑辅助层和隐藏卡片，同时固化当前主题、语言、间距、圆角、卡片顺序与可见内容。
- 共享实现：运行时新增 `WorkbenchCanvasExport`，多页签优先一次选择目标文件夹并批量写入，单页签使用另存，缺少文件系统 API 时逐份下载；导出文档内联计算样式、SVG sprite、洞察渲染器、复合下拉和图表交互。新增 `verify_exported_workspace_pages.mjs`，并同步 canonical 与 Skill bundled 资源树到 `ai-workbench-ux@1.5.7`。
- 验证：真实点击导出得到 `首页.html`、`详情页.html`、`列表页.html`；三份文件均只有一个 `[data-canvas-panel]`，没有页签/设置/CRM 导航 DOM、隐藏卡片或外部依赖，5 段内联脚本全部解析。三份文件在 1440×900、1024×768、390×844 重开时页面与画板横向溢出均为 0；深色导出根节点正确固化 `data-theme="dark"`。

## 1.5.6 - 2026-09-03

- 现象：窄屏页头的范围/区域筛选被角色图或相邻卡片遮挡，打开下拉时菜单被滚动容器裁切；设置态卡片隐藏按钮会浮到顶栏之上；嵌套网格部分卡片只能横向拖拽，无法向上或向下重排。
- 根因：Rich Header 移动端筛选组仍受左侧网格列的 `max-width` 与 `overflow-x:auto` 限制，隐藏按钮固定层级高于顶栏，拖拽命中使用单一 `elementFromPoint` 导致编辑辅助层截断目标识别。
- 强制规则：角色可见头部外溢统一为 `36px`，丰富页头卡片与顶栏保持 `42px` 顶部间距，简约模式不增加特殊间距；窄屏筛选组及其下拉必须位于角色图上层并在打开时解除裁切；隐藏按钮层级低于顶栏并避开顶栏区域；拖拽命中跳过隐藏按钮/缩放手柄，嵌套网格四方向均可重排。
- 共享实现：新增 `--wb-rich-header-top-gap` 与 `--wb-edit-hide-z-index` Token，更新 Rich Header 窄屏跨列层级和菜单裁切规则；画布运行时约束隐藏按钮位置并以 `elementsFromPoint` 过滤编辑辅助层；规范、模板、示例、提示词和版本标识同步到 `ai-workbench-ux@1.5.6`。
- 验证：localhost 浏览器复现并通过 1440×900、1024×768、390×844：Rich Header 卡片与顶栏间距为 42px，角色渲染盒外溢 42px（透明头部可见外溢目标为 36px），窄屏筛选组置于角色图上层且下拉菜单完整可见，页面横向溢出为 0；设置态隐藏按钮 z-index 900 且不与 48px 顶栏重叠；嵌套网格卡片可完成向上/向下拖拽。`node --check` 与 `verify_standalone_canvas.mjs` 均通过。
- 详情页修正：商机/客户洞察渲染器移除一级工作区专用的页面级富页头并标记 `.wb-secondary-page`；共享 Token/组件提供直接页头隐藏防回归，详情记录卡、面包屑、指标和操作保持不变。canonical 画布在重新内联后，一级首页仍保留 Rich Header，商机详情从记录卡开始，客户详情按既有身份去重规则从首个指标卡开始。

## 1.5.5 - 2026-09-03

- 现象：Rich Header 的人物头部仍在卡片内，未按参照图高出顶边 26px；角色切换只换图片、不换背景，无法与服装色形成整体识别。页头“全部区域”复合下拉点击后 `aria-expanded` 已变为 true，但菜单被 32px 高的横向控制组裁掉，视觉上没有弹层。
- 根因：所有透明 PNG 统一使用 220px 方形盒，没有补偿各图片不同的透明头顶留白；Rich Header 只读取固定主题 Surface，没有角色视觉映射。页面私有 Rich Header 规则又把 `.wb-page-control-group` 永久设为 `overflow-x:auto`，使绝对定位菜单落在滚动裁切区外；部分原生 option 未写显式 value，翻译文案还会改变业务值。
- 强制规则：桌面端按每张 PNG 的 alpha 顶边校准渲染尺寸，使可见头部高出卡片顶边恰好 26px并保持底部贴齐；八张角色资源映射七套服装色浅渐变，“用户/销售”共用粉色系，默认“总监”使用指定蓝色渐变。复合下拉打开时临时解除所属页面控制组的裁切并提升当前下拉层级，关闭后恢复窄屏横向滚动。
- 共享实现：新增 Rich Header 外溢、渲染尺寸和渐变 Token，组件以双层 background 合成角色渐变与主题 Surface；画布新增 `roleVisuals` 映射并在角色切换时同步图片、校准尺寸与渐变。共享 `select-interactions.js` 新增 `is-open` / `has-open-select` 状态，移除页面私有永久 overflow，并为缺少 value 的原生 option 固化视觉层稳定值；规范、模板、示例、提示词、canonical 与 Skill bundled runtime 同步到 `ai-workbench-ux@1.5.5`。
- 验证：canonical 与 Skill bundled 画布通过 runtime、standalone 孤立复制和 13 条路由校验，八张 PNG 均内联。真实浏览器中页头下拉四项全部可见，鼠标选择与 Arrow/End/Enter 键盘选择同步原生值并回焦；英文标签 “South China” 保持业务值“华南”。八角色实际形成七套渐变，alpha 可见头顶外溢测量为 25.73–26.38px；1024×768 设置态控件/人物交叠为 0，1440×900 深色英文与 390×844 深色英文页面溢出为 0，Skill 结构校验通过。

## 1.4.32 - 2026-09-02

- 原问题：用户说“按照 Skill 美化一下 HTML”或使用“优化、调整风格、重新设计”等宽泛措辞时，生成器可能只在现有页面上追加 CSS 或做局部视觉修补，没有按 Skill 的画布运行时和卡片规范重新生成完整 HTML。
- 根因：原 Skill 只规定了生成结果和缺失运行时的回归处理，没有在入口层定义宽泛改造措辞的执行模式；“美化/优化”容易被默认解释为增量编辑，输入 HTML 也容易被误当成必须沿用的 DOM 脚手架。
- 强制规则：此类宽泛请求统一进入完整重生成模式；输入 HTML 只作为业务数据、文案、单位、筛选、工作区、视觉意图和交互契约的证据，输出从 bundled canvas 按规范结构重组。禁止用覆盖 CSS、换色调距、包装旧 DOM 或保留不完整运行时冒充 Skill 生成结果。只有用户明确要求保留 DOM、只修指定问题或最小改动时才允许增量处理。
- 共享实现：更新 `fx-workbench-ux/SKILL.md` 的入口语义、`canvas-integration.md`、Skill 默认提示词、`CARD_SPEC.md`、`AI_PROMPT.md`、README、AGENTS 与分享指南，并将 canonical/Skill 双份资源树同步到 `ai-workbench-ux@1.4.32`；本次不改变业务组件 CSS 或运行时行为。
- 验证：Skill 结构通过 `quick_validate.py`；canonical 与 Skill bundled 资源一致，画布运行时和 standalone 校验通过；新分享包通过根目录结构、`.DS_Store` 排除、`unzip -t` 与校验和检查。

- 回归修复：CRM 导航模式下移除固定视口高度与 `overflow:hidden` 对画布长内容的裁切；设置抽屉打开时为工作台内容预留右侧空间，使抽屉停靠在工作台右侧而不遮挡正文；窄屏继续使用全屏抽屉。
