# AI工作台UX规范

规范 ID：`ai-workbench-ux@1.6.38`。本文中的“必须/禁止”是交付门槛，不是建议。

## 1. 不可变原则

- 必须保留来源页面的业务数据结构、数字、单位、标题、说明、筛选条件和交互入口。
- 禁止编造数据、替换业务术语、缩减列、隐藏异常值来改善视觉效果。
- 新卡片必须保存到 `workbench-card-library/cards/<card-name>/`。
- 必须先复用 `tokens.css` 和 `components.css`；只有现有组件无法表达真实业务结构时才新增类。
- 同一页面内的卡片必须共享标题层级、图标规格、内边距、圆角、表格密度和响应式断点。
- 用已生成 HTML 反馈规范时，附件只作为回归证据；不得把页面私有补丁、临时数据或近似的画布壳反向当成共享实现。先判定问题属于运行时、共享组件还是页面适配，再写入对应层。
- 用户以“按照 Skill 美化 HTML”“优化页面”“调整成工作台规范”“重新设计”等宽泛措辞要求处理现有 HTML 时，必须把输入文件作为业务数据、文案、单位、筛选、工作区和交互契约的来源，从 bundled canvas 按本规范结构重新生成完整 HTML；禁止只追加覆盖 CSS、替换色彩间距、包裹旧 DOM 或沿用不完整运行时。只有用户明确要求保留现有 DOM、只修指定问题或进行最小改动时，才允许增量修改。

- **1.6.31（2026-10-19）**：AI待协助使用独立 `.wb-ai-assistance-card`（`ai-assistance -> ai-assistance-list`），在信息列表页作为第 04 个示例；每条通知分别保留待办事项、来源对话、触发 Agent、回复/批复/处理类型和处理状态字段。默认待处理，以共享透明 `.wb-filter-segmented` 筛选待处理/已处理/全部，原生按钮使用 aria-pressed、唯一 Tab 入口和方向键/Home/End。列表筛选不得改写处理状态；单一查看对话操作复用紧凑按钮，未接服务只显示演示反馈，不模拟授权或批复成功。未知对话/Agent 不得作为真实数据补写，目录样例必须明确标注演示数据；数量从当前状态记录派生，空列表给出对应筛选说明，支持双语、六色系、浅深色及容器换行。

- **1.6.32（2026-10-19，覆盖1.6.31的布局与可见文案）**：AI待协助标题栏左侧保留标题，右侧使用32px高的共享透明分段筛选，当前筛选数量胶囊紧跟“全部”右侧；实际容器过窄时允许筛选组右对齐换行且不溢出。单一动作统一为“去处理 / Handle”，使用共享强调色实底主按钮与 --wb-on-accent 前景。Agent行只显示名称的浅色中性标签，不显示“触发 Agent”前缀或协助类型；协助类型仍保留字段元数据。删除行内待处理/已处理状态胶囊，待处理标题前使用共享橙色圆点，已处理无圆点；记录状态和双语可访问名称仍保留，筛选不得改变处理状态。

- **1.6.33（2026-10-19，覆盖旧数量与分隔线规则）**：AI待协助的每个筛选按钮在标签文字右侧内联显示该状态的记录数：待处理/已处理按各自状态计数，全部显示全部记录数，不随当前选项改写其他选项的数量。数字继承同一按钮的文字颜色并加粗，不使用独立胶囊；为0时隐藏数字且不占布局，仍保留稳定字段值。标签和数字分为独立子节点，语言切换不得清空数量。每个可见通知条目与共享信息列表一致使用1px --wb-info-list-divider底部分隔线，禁止使用浅色白色--wb-border-soft造成线条不可见；筛选后首尾条目保持相同分隔契约。

- **1.6.34（2026-10-19，覆盖1.6.31–1.6.33的筛选与已处理示例规则）**：AI待协助只承载未处理通知，删除全部筛选按钮/筛选组/类别文字与已处理记录DOM，不以隐藏面板保留已处理示例。标题右侧仅保留一个未处理数量，字段为pending-count，使用共享信息列表数字样式且不带胶囊，0时隐藏。数量从未处理记录派生，空队列显示“暂无需要你处理的AI通知”双语说明；保留待处理橙点、来源对话、Agent名称标签、去处理按钮及共享行底部分隔线。状态变更为已处理后从该卡片移除，不模拟业务处理成功。

## 2. 页面与卡片层级

- 模板工作台需要精简页签时，可将“模板库”“公司经营”“我的管理范围”“我的销售业务”组合到唯一的 `home` 工作区，将“商机项目洞察”“客户洞察”组合到唯一的 `detail` 工作区；“列表页”保持独立。合并只改变工作区承载，不得删减来源卡片、字段、筛选或下钻入口。若模板包含 CRM 外框，设置图标左侧的“显示CRM导航”开关必须持久化，并在开启时将完整画布挂入原有顶栏/左侧导航容器，关闭时恢复独立画布。
- CRM 外框模式下画布必须使用自然内容高度并交给页面滚动，禁止让 `workspace-card` 以固定视口高度和 `overflow:hidden` 裁掉长页面；设置抽屉打开时，工作台内容区必须通过右侧让位空间收窄到抽屉左边界，禁止覆盖正文。窄屏抽屉可按共享规则全屏显示。
- 合并后的 `home`/`detail` 顶层页签直接承载来源卡片；不得再渲染模板库、经营范围或洞察来源的页内子页签、页头和额外分组表面。来源卡片按原有稳定键平铺到当前工作区，同一业务队列、摘要事实和身份记录只保留一个权威卡片；列表页继续独立保留。

- 默认页面背景使用经典蓝色系的 `--wb-bg: #eef4fb`，不得改成纯白画布；切换色系时必须读取对应主题 Token。
- 主题风格默认使用“丰富”：主卡片读取 `--wb-card-surface`、`--wb-card-border`、`--wb-card-shadow` 和 `--wb-card-backdrop-filter`，其默认值保持 `ai-workbench-ux` 的 74% 半透明白 Surface、半透明白边框、同色轻阴影与 `22px/140%` 背景模糊。
- “简约”风格只允许通过 `[data-wb-style="minimal"]` 的共享职责 Token 将普通顶层主卡片改为白色实底、清晰描边、无阴影和无背景模糊，并将标题、指标和快捷入口图标改为同语义色淡色纯色底与弱描边，移除渐变、投影、发光、inset 高光和背景模糊；不得改写业务数据、布局、内部子面板或交互。深色模式下简约主卡片必须读取深色 `--wb-surface` 与 `--wb-border`，禁止产生白色亮块。产品明确设计为深色的重点卡必须标记 `.wb-special-dark-card`，简约模式不得把它改成白色或普通 Surface。
- 主卡片保持 `18px 20px` 内边距与 `16px` 圆角；任何风格不得覆盖同排自然等高和响应式规则。
- 小屏主卡片内边距收敛为 `16px`。
- 卡片间距使用 `12px` 或 `16px`，不得随意出现 13/15/17px。
- 同类快捷入口必须使用 `.wb-quick-grid > .wb-quick-card`，统一读取 `--wb-quick-card-min-height: 64px`、`--wb-quick-grid-gap: 16px` 与 `--wb-quick-content-gap: 10px`；模板库和所有工作台页签不得局部压缩或放大这三个尺寸。
- 对象入口使用共享 `.wb-object-entry-grid > .wb-object-entry-card`，目录只保留“左右完整 / 左右名称型 / 上下名称型”三种已批准样式，不展示上下完整型。完整型保留语义 SVG、对象名称、场景名称、数字、字段元数据和显式下钻；名称型只显示语义 SVG 与对象名称，不渲染场景名称或数字，但保留原有对象入口与显式下钻。左右布局保持 `64px` 等高；上下名称型使用共享纵向最小高度并居中排列，在桌面和 1024px 视口的一般目录内容宽度下一行五个，实际组件容器不超过 620px 时降为两列且不得溢出。目录中额外的 390px 移动端适配展示不计入正式变体数量：完整模式继续以单列呈现五个入口并保留全部信息与字段元数据；精简模式必须在一行内呈现五个入口，每项按“语义图标在上、对象名称在下”排列，网格间距为 0，并移除入口自身的背景、描边、圆角和阴影；图标必须保留与完整模式相同的分类身份色及 34px 浅色容器。精简入口 DOM 不渲染场景名称、数字或字段值节点，但继续使用原生按钮，保留合法路由、ARIA、至少 44px 点击高度与清晰焦点。
- 信息列表卡片使用共享 `.wb-card.wb-info-list-card`，在 AIPaaS 单页中按既有 `.wb-aipaas-variant-label` 标题格式连续展示 01 待办、02 提醒、03 关注三个示例；三张卡复用同一标题、可选来源总数、条目列表和底部“查看全部”结构，不使用内容切换页签。待办、提醒保留来源总数 6、5；关注来源没有总数时从 DOM 省略数量，不把可见三条推断为总数。各条保留原标题、时间或对象类型、说明、数值与单位、原顺序及稳定字段元数据；右侧时间、状态和对象类型统一使用共享 22px `.wb-status-tag` 胶囊。今天使用当前主题强调色的 `.is-attention` 高亮，明天、日期和普通对象类型使用 `.is-neutral`，商机偏移与报价失效倒计时等明确风险使用 `.is-risk`；风险标签读取共享风险色，不把普通日期误判为风险。胶囊文字按共享 `--wb-status-tag-tone-mix` 在浅色以 55%、深色以 35% 混合语义色与正文色，保证 10px 标签可读。中英文、浅深色和六套色系共用共享 Token。目录示例的业务动作未接服务时只显示既有演示反馈。
- M3E 业务组件统一命名为“欢迎卡片、AI洞察、对象入口、列表、ShareAgent对话”，五者共用置于内容设置之前的宽度、高度和圆角尺寸区。从组件面板拖入手机画布时，以释放指针命中的画布为准，自动采用该画布的“标准”内容宽度并水平居中；欢迎卡片与对象入口拖入 Web/桌面画布时仍采用 Web 标准宽。已经在画布中明确设置宽度的组件移动时不得被新建规则重置。对象入口卡片一级标题使用 `.wb-title-group.is-iconless`，不显示装饰图标或通用“打开 CRM”按钮；每个对象入口按钮及其显式路由仍是唯一业务下钻入口。
- M3E 整理控件在已整理状态仍显示完整填色按钮、语义整理图标与“整理”标签，不能缩成无背景对勾；已整理时禁用主动作但保留位置选择，整理后的撤销仍可用。对象入口和 AI 洞察的最小高度必须包含实际宽度下的标题换行、网格行数、操作区、内边距与边框；可调整高度不得压小至裁切业务内容，整理布局与预览必须使用同一有效高度。两种 AI 洞察形态复用共享结论卡/识别诊断中心结构及生成元信息，不复用旧大指标块界面。强调色按钮使用 `--wb-on-accent` 成对前景，禁止跨卡片读取未定义的私有色值导致蓝底黑字。
- **1.6.26 补充（2026-09-22，对应仓库规则 61）**：M3E 删除全局字体配置入口，不改卡片既有字体合同；整理控件增加独立“间距”按钮，其 `.wb-arrange-spacing` 弹层以 `.wb-arrange-spacing-head` 同行显示“页面间距 / Page spacing”和当前 `px` 值，使用原生 `input.wb-arrange-range[type="range"]`（`min=8`、`max=32`、`step=2`、默认 `16`），按稳定画框键持久化且不串改其他画框。独立业务卡按统一 gap 流式排布且不得重叠；单行卡保留 Standard 内容宽和左右各 `16px` 外边距，不把页面 gap 当外边距；同排双卡只在实际可用宽度足够时，先扣除统一 gap 再分配宽度，按分配后实际宽度测得的最大内容高度等高，不足则换行并恢复自然高度，内容超过画框时自动增高画框。保留原文案、字段、交互及 `locked/free` 语义；done 态保持完整填色整理按钮，仅禁用已完成主动作，间距与位置菜单仍可用。一次整理或间距调整必须作为一次撤销事务同时记录并恢复 frame（含高度、间距）与 groups，不能逐卡生成撤销或只恢复位置。已整理页面的有框/无框预览必须按实际预览宽度保持相同流式、gap、实测高度与自动增高规则，仅派生布局，不修改保存 doc；未整理页面的自由布局不被隐式整理。共享弹层为 `padding:16px`、`width:min(320px, calc(100vw - 32px))`、`max-width:100%`、`16px` 圆角、不透明 Surface 和浅阴影，不使用第二层模糊；滑杆触达 `44px`、轨道 `4px`、滑块外径 `16px` 且有白边与阴影。WebKit/Firefox 都由 `--wb-range-progress` 百分比绘制左侧强调轨道；调用方按 `(value - 8) / 24 * 100%` 同步进度（默认 `33.333333%`）和可见 px 值。颜色由 `--wb-arrange-accent/track/surface/foreground/muted` 映射编辑器 Palette，未映射时读取共享强调色、轨道、不透明浮层和文字 Token；尺寸由 `tokens.css` 提供。只对这些专用类设置样式，不扩大为通用 input 规则；保留原生方向键/Home/End、双语标签、Esc 关闭回焦、focus-visible、六色系、深色与 reduced-motion 支持。
- M3E 预览右下角提供“去掉设备边框 / 显示设备边框”可逆操作，并以 `aria-pressed` 标记无框状态。无框时去掉设备黑边、设备圆角与投影；Web 内容按浏览器可用宽度适配并铺满视口，不为控制菜单预留侧边空白；手机内容保持手机宽度并水平居中，窄于手机的视口允许适配，长内容可滚动。仅派生预览布局，不改变已保存的画布、组件尺寸或内容，保持导航、返回、关闭及输入交互。
- 默认禁止卡片套卡片。确需一个主卡片包含多个分析模块时，内部模块必须使用 `.wb-subpanel`，读取 `--wb-subpanel-surface`、弱边框与 `--wb-subpanel-shadow`；该浅投影只用于拉开主卡与业务子面板层级，禁止复用主卡 `--wb-shadow` 或再次启用背景模糊。子面板内的紧凑事实块使用 `.wb-inner-tile` 与对应 Surface/Shadow Token，禁止自行混入近似白色。
- 需要由多个业务模块组成一张卡时，外层必须使用 `.wb-card.wb-composite-card > .wb-composite-body`；并列或响应式模块使用 `.wb-composite-split` / `.wb-composite-grid`，每个业务模块继续保持 `.wb-subpanel`，不得把多个无关区域直接平铺成无层级的普通卡片。
- 商机阶段、试料反馈、报价闭环等属于同一业务链路的紧凑分析必须由一个有明确总标题的主卡片承载，内部使用 `.wb-analysis-group > .wb-subpanel`；每个子模块标题左侧使用语义 SVG 图标。子模块中的四个紧凑指标默认保持两列排列，不因中等容器宽度提前退化为单列。
- 单条上下文事实带四项经营指标时，上下文必须作为独占首行的标题区，四项指标在下一行使用语义色软底指标卡；窄容器按两列、单列响应。该摘要只出现一次，后续判断或动作区不得重复整组事实。
- 相邻权威记录已经完整呈现同一客户、项目或对象身份时，后续摘要禁止再次渲染同名身份大区块；经产品确认可移除重复身份，只保留不重复的指标事实，并使用 `.wb-summary-metric-grid.wb-metric-grid > .wb-metric` 作为同级语义色指标卡。每张指标卡保留语义 SVG、名称、值、单位、口径与原有下钻，不能用一条无底色分隔栏替代。
- 经营基本盘、当前阶段等“标题/口径 + 四项事实”摘要在需要紧凑表达时使用 `.wb-card.wb-compact-baseline-card`：标题区使用 `.wb-baseline-head-copy + .wb-baseline-meta`，指标区继续使用 `.wb-summary-metric-grid.wb-metric-grid > .wb-metric`。紧凑变体统一读取 `14px 16px` 外层内边距、`12px` 标题区间距、`96px` 指标最小高度与 `10px 12px` 指标内边距；禁止保留大幅空白或另建页面私有指标组件。
- 同一分析行的两张卡默认各占 6/12 并自然等高；当业务内容或明确视觉反馈要求一侧更窄时，允许通过共享分析跨度 Token 使用 5/12 + 7/12，禁止写页面私有近似宽度。仅当实际容器宽度不足以容纳内容时才整行降为单列；禁止使用过早的视口断点让本可并排的卡片变成通栏，也禁止把环图、说明或操作挤出卡片。
- 并排卡片在同一网格行必须自然等高：网格使用 `align-items: stretch`，直接子项使用纵向 flex，卡片使用 `flex: 1` 或 `height: 100%` 填满可用行高，左右底边严格对齐。
- 禁止通过固定像素高度实现等高；同排高度由该行最高内容自适应决定。响应式变为单列后恢复各卡片自然高度。
- 优先直接使用 `.wb-equal-grid`，其直接子项内的 `.wb-card` 已包含统一等高行为。
- 两行分析网格的下排内容明显少于上排时，必须使用 `.wb-compact-tail-grid` 或等价的 `minmax(0, 1fr) auto` 行轨道：上排吸收剩余高度，下排按内容自然收拢；同一排卡片仍保持 stretch 等高，禁止让两排平均分配空白。

### 2.1 弱色画布玻璃质感边界

- 玻璃效果只用于顶层独立卡片、工具栏和筛选控件；内部子面板与紧凑事实块不得再次应用背景模糊，只允许使用共享 `--wb-subpanel-shadow` / `--wb-inner-tile-shadow` 的浅层级投影。表格行和状态标签不得增加投影，固定操作列只允许使用横向边界阴影避免滚动内容透出。
- 质感由四个固定职责共同形成：当前色系弱画布、74% 白色 Surface、半透明白边框、当前强调色低透明阴影。四项必须读取 Token，不得在组件中散落近似值。
- 卡片阴影固定为 `0 18px 48px color-mix(in srgb, var(--wb-accent) 10%, transparent), inset 0 1px 0 rgba(255, 255, 255, .78)`；禁止扩大透明度、叠加深色投影或制造悬浮营销卡效果。
- 控件使用 66% 白色表面、18px 模糊和更弱阴影；控件不能比主卡片更突出。
- 玻璃 Surface 后方只能是当前色系的连续弱色画布，不添加渐变光球、图片纹理、噪点、网格或装饰色块来强化透光感。
- 深色模式使用不透明深色 Surface 保证对比度，不强制模拟浅色玻璃；语义色和层级保持一致。

### 2.2 跨页签卡片组合

- 一个页签需要承接其他页签已有能力时，必须直接复用现有卡片渲染器、组件或数据适配层；禁止复制现有卡片 HTML 后形成第二套实现。
- 每个组合区域使用 `.wb-card-composition`，直接子项使用稳定且唯一的 `data-wb-card-key`；需要跨两列的卡片使用 `data-wb-span="all"`。窄屏自动转为单列，不得写固定像素高度。
- 同一页签内，同一业务队列、统计事实或操作入口只能由一个权威卡片承载。若综合卡已经包含审批、通知或团队事项，不得再并列挂载其子集卡片造成重复计数或重复入口。
- 复用卡片时只替换当前页签的数据权限、管理关系和筛选上下文；业务标题、字段、单位、去重主键、下钻和操作语义必须保持来源契约。
- 只有现有组件无法表达缺失业务结构时才新增卡片，并继续遵守 `cards/<card-name>/`、公共 Token、主题、多语和交互要求。

## 3. 卡片头部

- 页面级页头必须使用 `.wb-header > .wb-title-group` 的单列结构，`h1` 在上、说明 `p` 在下并占据同一内容列；标题必须保持 `writing-mode: horizontal-tb` 和完整词组横向阅读，禁止复用 34px 图标列或因可用列过窄而逐字竖排。页头标题组可在窄屏按完整词组换行，但不得压缩为单字宽度。
- 丰富主题下的页面级页头默认使用 `.wb-header.wb-rich-header-card`：以 `220px` 设计高度组织横向卡片，标题/说明位于左上，周期、枚举筛选或同级紧凑命令位于左下，右侧使用 `.wb-rich-header-role > img` 展示底部贴齐的透明角色形象。桌面端必须按 PNG 透明头顶留白校准形象尺寸，使可见头部高出卡片顶边恰好 `36px`，且卡片与顶栏保持 `42px` 顶部间距；不得直接按统一图片盒上移造成不同人物误差或底部悬空。卡片 Surface、Border、Shadow、Blur 和圆角必须读取共享 Rich Header/Card Token；不得把角色图当背景图、遮挡标题控件或裁掉复合下拉弹层。窄屏页头筛选组可跨越角色图所在列并置于其上层，简约主题隐藏角色图且不保留这段特殊顶部间距。
- 画布设置在“色彩主题”下方提供“头部卡片”区。丰富主题显示共享复合下拉“角色形象”，选项和值必须来自 `role-image/` 的真实文件名：`分析师-女.png`、`分析师-男.png`、`客服.png`、`总监.png`、`服务工程师.png`、`服务总监.png`、`用户.png`、`销售.png`，默认 `总监.png`；简约主题只显示不展示角色形象的状态说明，不显示无效选择器。八张资源按服装主色绑定七套浅色渐变，“用户/销售”共用粉色系；切换角色时所有 Rich Header 必须同步切换渐变。默认“总监”使用 `linear-gradient(88deg, rgba(229, 238, 255, 0.20) 33.75%, rgba(144, 181, 255, 0.20) 82.55%), rgba(255, 255, 255, 0.74)`。选择结果写入画布配置并随刷新、导出页面和重置保持；可分发单文件必须把全部八张 PNG 内联为数据资源，复制后仍可切换。
- 丰富页头在窄容器中可以按共享响应式 Token 缩短到 `184px` 并缩小右侧形象，但标题、说明、32px 控件、下拉弹层和角色图不得发生不可访问的遮挡或造成页面横向溢出；筛选控件与下拉弹层必须在角色图之上，菜单打开时不得被页头、相邻卡片或横向滚动容器裁切。角色图只承担视觉识别，使用空 `alt`/`aria-hidden`；可访问的当前选择由设置下拉提供。
- 富页头只属于一级工作区页面（例如首页经营工作台）；客户/商机洞察详情页、列表页及其他下钻二级页面不得渲染页面级 `.wb-header` 富页头。二级页面应直接以记录卡、首个业务指标卡或列表首卡开始，详情内的记录操作、面包屑和业务事实保持不变；使用 `.wb-secondary-page` 标记二级容器，公共组件默认隐藏其直接页面级页头，防止后续渲染回归。
- 页面级页头同时包含周期与枚举筛选时，两个组件必须放入 `.wb-page-control-group`：桌面端按内容宽度自然展开、禁止设置固定或最大宽度并禁止换行，始终左右排列；窄屏使用整行横向滚动而不是上下堆叠或造成页面横向溢出。
- 使用 `.wb-card-head > .wb-title-group + .wb-title-meta`。
- 卡片标题与说明默认使用上下结构；带图标子标题的两列网格只允许包裹“图标 + 标题文案组”，不得直接把 `h2` 与 `p` 分配到左右网格导致逐字换行。页面级标题禁止使用该两列图标结构。
- 标题为 15px/21px、加粗；说明为 11px/17px；禁止卡片内部使用页面级大标题。
- 标题图标容器固定 `34x34px`，图标固定 `21x21px`，圆角 `6px`。
- 分析卡内部模块标题栏必须紧凑：最小高度 `44px`、内边距 `10px 16px`，标题垂直居中；带独立分隔线的贴边标题卡必须使用 `.wb-flush-card > .wb-flush-head + .wb-flush-body`，清除标准卡片的外层内边距，禁止外层卡片内边距与标题栏内边距叠加形成双重顶部留白。`.wb-flush-head` 与 `.wb-flush-body` 必须是卡片的直接子项；正文读取 `--wb-flush-body-padding: 16px 20px 20px`，手机收敛为 `16px`，禁止被无样式中间容器隔断后退化为 `0` 内边距。
- 所有图标必须按所在标题、操作或状态的真实语义，从现有 SVG 图标或同一图标库中选择对应的 `currentColor` 图标；禁止用中文、英文、字母缩写、数字或标点等可见文字生成或代替图标（例如用“试”“价”“审”“通”充当图标），也禁止 emoji 和手绘风格不一致的 SVG。找不到完全匹配的图标时选择语义最接近的库内图标，不得退回文字图标。
- 把 `元`、`¥`、`$`、货币代码或其他可见字符转换成 SVG path 仍然属于文字式图标，必须禁止。金额指标使用钱包、钱币或钞票等纯图形语义图标，报价申请使用文档或剪贴板图标；共享 SVG 增加 `.wb-semantic-icon`，图形本身不得依赖界面语言。
- 报价管理对象入口必须使用可见的文档或剪贴板语义 SVG；列表类线框若因仅有开放路径而在当前填充式图标系统中不可见，必须更换为闭合可见的语义图标，不得交付空图标底座。
- 语义色映射：常规蓝、分析青、成功绿、提醒橙、风险红、辅助紫。颜色不能仅用于装饰，且同义状态全局一致。
- AI 识别诊断卡中的结论摘要属于 AI 辅助分析语义，必须使用共享 `--wb-ai-insight-border: rgba(79, 104, 255, 0.20)` 的 `1px solid` 描边，并读取 `--wb-ai-insight-surface: linear-gradient(96deg, #FFFFFF 0.58%, #EBF2FF 102.07%)`；不得把建议背景默认染成黄色。只有结论本身明确表达警告时，才在当前诊断行内部使用橙色状态文字，整块背景仍保持指定的 AI 渐变语义。深色模式可读取共享暗色可读变体，但必须保持同一蓝紫识别关系与 `96deg` 方向。
- AIPaaS 的结论卡与识别诊断卡必须使用同一 `.wb-ai-generation-meta`，直接显示固定格式 `yyyy-mm-dd HH:MM` 的模拟生成时间，不再显示“生成时间 / Generated at”可见标签。时间文字统一读取 `--color-neutrals11`，使用 `Source Han Sans CN` 首选字体、12px/18px、400 字重、normal 字形，并关闭 `liga`/`clig`。结论卡移除“AI辅助归纳 · 基于CRM可核验事实”辅助标签；其生成元信息与后续操作必须置于共享 `.wb-ai-generation-row` 底部操作行，在容器足够宽时元信息靠左、操作组靠右并垂直居中，窄容器可安全分行但不得溢出或改变键盘顺序。识别诊断卡仍将元信息放在标题栏右侧。`.wb-ai-regenerate` 保留 32px 键盘/指针命中区，但可见状态不得绘制背景、边框或阴影，只显示已批准的 16×16 双路径刷新图形；浅色图形为 `#181C25`，深色读取共享可读 Token。按钮保留双语 `aria-label`、完整 hover/focus 状态，并在未连接生成服务时复用目录演示反馈；禁止用“新”、`AI`、数字或标点充当图标。窄容器内生成元信息组不得换行或溢出。识别诊断卡不再并列显示总事件胶囊；各识别器原有事件数量仍保留。
- 图标背景、图标前景和投影必须读取同一个 `--wb-tone`；投影固定用 `color-mix(in srgb, var(--wb-tone) 30%, transparent)`。禁止红色图标使用蓝色投影等跨色系组合。

## 4. 控件

- 视图/时间切换使用 `.wb-segmented`，当前项用 `aria-selected="true"`。
- 分段控件的激活项在 hover、focus 与 active 状态都必须保持当前主题的强调色背景和白色前景；禁止激活项 hover 后退回白色、普通 Surface 或未选中态。
- Rich Header 角色 Tab 使用 `.wb-role-switcher > [role="tab"]`：选中项维护 `aria-selected="true"` 与唯一 `tabindex="0"`，支持鼠标、左右方向键、Home/End，并在中英文切换时同步可见标签与 Tablist 可访问名称。角色缩略图直接使用对应 `role-image/` PNG，禁止用字母或缩写替代。

- 隐藏卡片状态继续在同一画布配置中按稳定卡片键持久化，但设置态底部隐藏数量和还原命令必须仅统计、仅恢复当前页面，不得把其他页面的卡片数量混入或跨页还原。
- 画布设置按钮在深色模式必须读取可见的文字/图标色与深色控件 Surface；数值滑杆必须以强调色绘制滑块左侧已完成轨道，并同步 WebKit 与 Firefox。设置面板首项提供“主题风格：简约/丰富”，默认选中丰富，支持键盘方向键、Home/End 与中英文。

- 设置抽屉压缩画布后，编辑网格必须按剩余可用宽度降列：窄桌面优先两列或单列、移动端单列；禁止为了保留桌面列数把卡片压到内容溢出。
- 任何生成页只要出现画布设置抽屉，就必须同时保留完整隐藏卡片运行时：`#canvasCardHide`、`#canvasHiddenBar`、`#canvasRestoreHidden`、`hiddenCards`、`hiddenCardState` 和 `--wb-edit-guide-*`。只保留设置面板而省略隐藏/还原/引导能力视为运行时不完整，必须从 bundled canvas 重新生成。
- 回归审计发现的图标替代、筛选替代和编辑态替代不得靠页面私有选择器解决。可见字符（中文、英文、缩写、数字、标点）不能出现在图标容器中；页头枚举筛选不能绕过 `.wb-select.wb-page-filter`、原生值/change 契约和 `.wb-page-control-group`。

- 可横向滚动的控制组已经发生内部溢出时，复合下拉必须保持滚动位置，并将菜单临时挂载到 body 的共享 `.wb-select-portal` 层。弹层继承当前根的主题 Token，按触发器位置约束在视口内，空间不足时向上展开；关闭后还原原 DOM 位置和样式。不得通过解除滚动裁切使组回到 scrollLeft=0 并将触发器推到屏幕外。无横向溢出的控件组继续使用原有解除裁切逻辑。

## 5. 字体、指标与数字

- 页面和卡片文字必须使用内容驱动的共享字号；禁止用包含 `vw` 的 `clamp()` 随视口缩放字体，禁止负 `letter-spacing`。长中文/英文标签应自然换行或省略并保留可访问完整文本，不得逐字竖排、裁切或把连接装饰线推到网格外。

- 全站拉丁字母和数字必须优先使用 `Inter`；基础字族 Token 以 `Inter` 为首位，中文字符自然回退到苹方、微软雅黑等既有中文字体。禁止组件单独改回 Arial、Plus Jakarta Sans 或 SF Mono 优先。
- 数字使用 `.wb-number` 或 `--wb-font-number`，该 Token 同样以 `Inter` 为首位并开启等宽数字。
- 核心值 28px/32px；卡片标题旁元信息 10px/16px；单位与次级说明 11-12px。
- 单位紧邻数值，不拆到不可预测的新行。长说明允许换行，关键实体可用省略号但必须有 title/详情入口。
- 指标值、百分比、数量和单位不是句子，不得在末尾保留逗号、句号等终止标点；标点只用于完整说明句。
- 纵向补充事实使用 `.wb-fact-list`，说明为 10px/16px，结果值至少 15px/20px、700 字重，保持清晰的说明/结果层级。
- 指标组优先使用 `.wb-metric-grid` 和 `.wb-metric`，语义色通过 `--wb-tone` 设置。
- 独立展示的百分比或比率必须同时显示指标名称，例如 `67%` 下方显示“整体赢单率”；禁止只显示无上下文的数值。
- 紧凑补充指标可使用 `.wb-soft-metric`：以对应 `--wb-tone` 的低透明色形成浅色背景和弱边框，不增加模糊或阴影；同组指标按风险、提醒、常规等真实语义分配色块，深色模式读取相同职责 Token。
- 字段覆盖类标签中，未完整项只使用橙色文字，不使用成功色或提醒色底块；圆形数量徽标的数值与说明必须作为一个紧凑文字组整体居中，说明不得贴住或越过圆环。
- 审批、通知等紧凑队列卡的数量放在标题同一行，以 `.wb-count-pill` 的淡色胶囊显示纯数字；标题已表达数量语义时不重复“项/条”。说明文字独占下一行通栏，不得被数量或箭头压缩。

## 6. 图表

- 每个图表必须放入 `.wb-chart-frame` 或等价的边界容器：容器及其所在 Grid/Flex 子项必须 `min-width: 0`、`max-width: 100%`，并在图表边界裁切装饰性绘制；标题、坐标标签、图例、数值和交互点必须始终位于卡片内。禁止依赖卡片外层裁切来掩盖仍然越界的业务内容；空间不足时必须重排、降低列数或重新计算图形几何。
- 包含文字、圆点、图标或固定描边的 SVG 图表禁止使用 `preserveAspectRatio="none"` 做非等比缩放。必须使用等比缩放，或让 `viewBox` 与实际渲染宽高同步并重算坐标，保证文字、圆点和描边不被横向或纵向压扁。
- 紧凑进度条固定 8px 高；堆叠柱固定 20px 高；圆角不超过 5px。
- 堆叠图必须有同序图例，颜色顺序在所有卡片中保持一致。
- 柱状图图例默认使用 `.wb-chart-legend`，水平居中并位于绘图区上方；禁止把图例塞在柱图下方造成视线回跳或挤占横轴标签空间。
- 来源数据包含行业、部门等结果分布维度时，卡片必须保留维度筛选和每行原始分段数据、赢单率等结果指标；禁止只保留总体环图而删除来源中的分布明细。
- 饼图/环图的可读直径不得小于 120px，中心标签不可与环重叠；旁侧说明区必须使用 `minmax(0, 1fr)` 防止逐字换行。
- 图表与说明并排时，图表是主视觉：图表轨道至少获得可用宽度的 52%，说明区使用有上限的窄轨道；若空间不足则整体转为上下布局，禁止压缩图表来容纳长说明。
- 结果、占比、异常等补充事实默认采用“说明在上、数值在下”的纵向结构；数值不得挤占说明的可读宽度。
- 柱段、堆叠柱段、饼图和环图的每个色块必须支持指针 hover 与键盘 focus，并显示统一数据浮层。浮层必须包含系列/分类名称、原始值、单位及适用时的占比，使用共享 Tooltip Surface、Border 和 Shadow Token；深色模式同步切换，不得只依赖浏览器 `title`。
- 图表首次呈现采用 `1000ms`、`easeOutQuart` 等效缓动的增长/绘制动画；同一图表数据项的递进延迟不超过 `160ms`。柱图只使用横向或纵向缩放，环图只使用描边绘制，不得改变布局或让数值跳动。
- 图表交互反馈保持在 `200ms` 内；`prefers-reduced-motion: reduce` 时必须关闭首次呈现动画和递进延迟。
- 图表必须具备可访问的文字摘要或 `aria-label`，不能只用颜色传达数值。
- 禁止 3D 图表、强渐变图表、发光大面积背景和无业务含义的装饰图形。

## 7. 表格与列表

- **1.6.27（2026-09-22）**：M3E 业务组件新增“列表 / List”，直接复用目录对象列表的 `.wb-card.wb-aipaas-table-card`、无图标标题、`.wb-filter-segmented` 和 `.wb-table-wrap > .wb-table`，样式上收至共享 components，禁止私有重绘。默认保留管理范围经营对比的七列、四行与风险色；销售人员七列和客户级别六列使用既有来源数据，不补造同构指标。分组使用稳定键、漫游焦点与方向键/Home/End，非当前面板不可访问；标题组使用自然 flex basis，窄屏纵向排列时不得把桌面宽度基准转成固定高度；编辑器和预览按各面板实际最大自然高度测量，切换不裁切、不覆盖相邻卡片、不改保存文档。宽表只在容器内滚动，所有字段保留元数据和单位。尺寸区位于内容前；新建采用目标手机/Web 的 Standard 宽度，已有宽度不重置；标题、说明和默认维度可保存并撤销。同步根共享层、M3E 镜像及各卡生成样式，浅深色与多语共同验证。
- 数据表使用 `.wb-table-wrap > .wb-table`；表头 10px，单元格 11px，行高由 12px 上下内边距形成。
- 表格容器、表头、默认行、交替行与行 hover 必须分别读取 `--wb-table-surface`、`--wb-table-head-surface`、`--wb-table-row-surface`、`--wb-table-row-alt-surface` 与 `--wb-table-row-hover-surface`。深色模式禁止继续使用 `white` 或浅色半透明值混合表头和行背景；复用表格类的页面必须按组件本身匹配暗色样式，不得依赖某个业务祖先选择器。
- 宽表格必须保留全部列并允许横向滚动，禁止为了移动端删除列。
- 状态使用 `.wb-stage`，风险状态使用 `.is-risk`；项目名称加粗，辅助信息弱化。
- 列表状态、处置结论和风险等级需要紧凑标签时使用 `.wb-status-tag` 与语义色类：标签按内容宽度收拢，统一 `22px` 高、`0 7px` 内边距、文字水平垂直居中；禁止拉伸到整列宽度，禁止宿主表格的通用 `span` 规则覆盖其语义文字色或 `inline-flex` 布局。
- 表格负责人使用 `.wb-person-label > .wb-avatar + 文案`。头像固定 `22px`，语义 SVG 固定 `14px`，必须在圆形强调色背景中双轴居中并使用 `--wb-avatar-foreground` 亮色前景；SVG 子节点继续读取 `currentColor`，禁止被宿主表格文字色覆盖为黑色。
- 列表项之间使用 1px 分隔线，hover 只改变弱背景，不改变行高。
- 子面板底部的口径、数据边界或推断限制说明使用共享 `.wb-boundary-note`、灰色 `--wb-note-surface`、圆角和内边距，不使用贯穿式顶部描边；说明与子面板边缘保持共享间距。
- 行内存在标题、说明和多个操作时，操作必须使用 `.wb-action-row` 独占内容区第三行并横向排列，不得用右侧窄列持续挤压标题与说明。
- 当列表项只保留一个统一处理入口时，必须使用 `.wb-inline-action-list > .wb-inline-action-item`，将单一 `.wb-inline-action` 放在正文右侧并与标题/说明组同一行；同一列表不得混用多个不同文案的尾部按钮。
- 宽表格的“快捷处理”列使用 `.wb-action-column` 固定在滚动容器最右侧，表头、默认行、交替行和 hover 必须读取完全不透明的 `--wb-action-column-*` Surface，配合 `--wb-action-column-shadow` 遮住其下滚动的业务文字；禁止使用半透明行 Surface 造成文字透出。操作使用高度固定为 `--wb-primary-action-height: 32px` 的 `.wb-primary-action` 主题强调色按钮，横向滚动时业务列可移动，处理入口必须持续可见。
- 分页/条数信息使用 `.wb-table-foot`。空状态使用 `.wb-empty`，不得伪造示例数据填充。

## 7.1 关系链路

- 产业链、组织链或供需关系要求表达上游与下游时，使用 `.wb-relation-flow` 纵向组织层级：上游节点在上、下游节点在下，并通过 `.wb-relation-branch` 的连续线连接。禁止把有方向的层级压成无连接的同排平铺卡片。
- 层级方向已由标题、节点顺序与连续连接线清晰表达时，可以移除“上游/下游”等冗余可见层级标签，但每一层必须保留随中英文切换的 `aria-label`。分支节点使用 `.wb-relation-children > .wb-relation-node`，保留全部实体名称、角色、项目数量和原有下钻。三分支使用 `.wb-relation-flow.is-three-way`：横线左右端必须精确落在首尾节点中心，并与三个节点的竖线连续相接。窄容器改为纵向节点链时，连接线、层级方向与实体顺序必须保持。

## 8. 色彩与主题

- 只使用 `tokens.css` 中的令牌；禁止在卡片 CSS 中新增接近但不同的蓝、灰、玻璃透明度、边框色或阴影。
- 页面不能被单一强调色支配，语义色只用于图标、状态、图表系列和少量强调。
- 必须兼容 `[data-theme="dark"]`。深色模式保持语义色，切换背景、文字、边框和阴影令牌。
- 深色模式的指标、快捷入口、元信息胶囊和列表行必须以 `--wb-surface-strong`、`--wb-surface-hover`、`--wb-meta-surface` 及对应表格 Surface 为基底；身份色只以低透明度混入深色 Surface，禁止通过 `color-mix(..., white)` 或遗留浅色硬编码制造近白卡片、灰白表格或过亮 hover。
- 必须支持与主画布一致的 6 套色系：经典蓝 `#eef4fb/#4f8cff`、云杉绿 `#eef7f3/#168b68`、珊瑚橙 `#fff4ed/#e66a35`、鸢尾紫 `#f5f1fb/#7856d8`、石墨红 `#f9f1f3/#c3475c`、中性灰 `#f1f4f6/#425a70`。前者为画布色，后者为强调色；旧 `indigo` 配置读取时迁移为 `iris`，新输出不得再写入旧键。
- 色系切换只改变主题职责 Token，不得覆盖成功、警告、危险和数据分类色。
- 正文与背景对比度至少 4.5:1，较大文字至少 3:1。

## 8.1 多语

- 规范组件和示例页面必须支持中文/英文切换，并同步更新 `<html lang>`。
- 所有 UI 标题、控件名称、辅助说明、表头、分页和可访问名称都必须进入同一多语字典；禁止只翻译页面标题。
- 数字、单位和日期按语言正确格式化，业务专有名词可以保留原文，但不得出现中英文混杂的系统控件。
- 中英文切换不能改变卡片宽高规则、数据含义、交互状态或字段数量；英文长文本必须参与三个视口及设置抽屉展开后的实际内容宽度检查。重点指标的长英文单位/标签在移动宽度可整组换到数值下一行，禁止为了强制同排造成卡片内部溢出。

## 9. 响应式与稳定性

- 必测视口：`1440x900`、`1024x768`、`390x844`。
- 900px 以下多列指标变两列；640px 以下变单列，卡片头部上下排列。
- 固定格式组件必须使用稳定尺寸、`minmax(0, 1fr)` 和明确网格轨道，数据变化不能让按钮、图例或卡片整体跳动。
- 画布抽屉、侧栏或相邻面板改变实际内容宽度时，图表和图表型列表必须根据容器宽度重排或重算坐标，不能只依赖浏览器视口断点；任何图表内容越过卡片内边界均视为交付失败。
- 禁止文本与图标重叠、跨卡片溢出、逐字竖排、左右同组卡片底边不齐。
- 宽表格可横向滚动；页面本身不得产生无意的横向滚动。

## 10. 可访问性与交互

- 使用语义化 `section/article/header/table/button`，按钮不能用 `div` 模拟。
- 图标若纯装饰设置 `aria-hidden="true"`；只有图标的按钮必须有可访问名称。
- 筛选、标签和表格必须有对应 `aria-label`、`role` 或原生标签关系。
- 尊重 `prefers-reduced-motion`；常规状态反馈不超过 200ms。只有第 6 节定义的图表首次呈现允许使用 1000ms，且不得改变布局。
- 数据刷新、跳转 CRM、筛选和分页的原有事件绑定必须保留。
- 三个工作台中的跨页签下钻必须复用共享 `workspace-routing.js`：销售线索进入列表页，客户事实/客户洞察进入客户经营洞察，商机事实/商机洞察/明确的商机查看动作进入商机项目经营洞察。显式 `data-wb-route` 优先于动作文案解析；“新建、创建、添加、处理、维护、补充、修订、填写、继续、导出、刷新”等命令不得被路由器误判。列表页返回入口必须记住来源工作台；明确的详情/查看动作必须到对应详情型页签，禁止只显示“入口已就绪”提示。
- 当具体入口的产品语义与通用动作文案映射不同时，合法的显式 `data-wb-route` 必须保持不变，注册器不得用动作文案推断覆盖。表格中的项目名、客户名、公司名等实体值需要跨页签下钻时，值本身使用共享 `.wb-entity-link` 按钮并保留 `data-wb-route`；禁止扩大为整格或整行点击，也禁止只绑定鼠标事件而缺少键盘焦点。
- 列表实体已提供详情入口时，点击后必须进入真实详情视图并提供返回列表；演示详情只能复用该行已有字段，不得编造新事实。详情与列表切换必须保留当前搜索和分页状态，键盘焦点进入详情返回按钮并在返回后回到列表搜索入口。

## 11. 禁止项

- 禁止 emoji 图标、随机渐变背景、装饰光球、超大标题、营销页式卡片堆叠和过度玻璃拟态。
- 禁止超过 24px 的卡片圆角，标准卡片必须使用 16px。
- 禁止阴影叠加、卡片嵌套卡片、每个模块使用不同边距和标题结构。
- 禁止将文案写进图片、用纯 CSS 图形替代既有图标库、通过缩小字体掩盖布局问题。
- 禁止修改业务事实来迁就模板。

## 12. 交付检查

- 文件位于 `cards/`，且引用公共 tokens/components。
- 数据、文本、单位、筛选和交互与来源一致。
- 标题、图标、控件、图表、表格均复用标准组件。
- 跨页签组合使用唯一 `data-wb-card-key`，同一业务队列没有重复卡片、重复计数或重复入口。
- 三个必测视口无重叠、截断、异常横向滚动或等高偏差。
- 键盘焦点、hover、空状态、加载状态、错误状态和深色模式已检查。
- 公司经营、我的管理范围、我的销售业务中的销售线索/客户/商机入口分别到达列表页/客户经营洞察/商机项目经营洞察；查看洞察和查看商机到达对应详情型页签，列表返回原工作台，新建与处理类命令不被拦截。
- 显式 `data-wb-route` 未被动作文案推断覆盖；跨页签表格实体使用 `.wb-entity-link`，点击和键盘激活均到达显式目标，且未把整格或整行变为隐式点击区。
- 列表中的每个实体链接进入由当前行 7 个原始字段组成的销售线索详情，返回列表后原搜索与分页状态不变；详情未出现来源行之外的新增业务事实。
- 打开画布设置后无需额外开关即可拖动所有已注册大区块和内嵌卡片；实际检查同网格重排、同范围跨网格重排、刷新后归属/顺序持久化、空网格收起、恢复默认归属/顺序和关闭设置退出编辑态。
- 设置抽屉不包含重复的顶层页面页签；打开设置后通过顶部工作区页签切换，每次只有对应工作区可见、可编辑。隐藏计数和“还原本页”不混入或恢复其他页面的卡片。
- 编辑态四方向放置线均为清晰主题强调色且完全位于目标卡片内；左右缩放控件不被任何祖先裁切。实际检查隐藏页面区块和内嵌卡片、唯一计数、刷新/保存后保持、一键还原及重置清空；隐藏操作不得触发卡片业务命令或拖拽。
- 图表每个色块均可通过 hover 与键盘 focus 读取统一浮层；入场动画、递进节奏和 reduced-motion 降级已检查。
- 图表与说明的主次宽度、补充事实的上下结构及内部标题栏 44px 紧凑间距已检查；贴边标题卡顶部不得残留标准卡片外层内边距。
- 图表边界、标签、图例、数值和交互点均未越过卡片；SVG 文字、圆点、图标和描边在容器缩放后仍保持正确比例。
- 未引入新的随意颜色、圆角、玻璃透明度、模糊值、阴影或未经批准的组件变体。
- 同色图标背景与投影一致，6 套色系、中文/英文、浅色/深色组合均可切换。
- 所有图标均为与标题、操作或状态语义匹配的 SVG/统一图标库图标，不含用中文、英文、缩写、数字或标点生成的文字图标。
- 枚举筛选使用圆角轻投影的共享弹层而非系统选项面板；鼠标、键盘、焦点回退、原生 `change` 事件、深色模式与中英文均正常；页头横向控制组中的菜单打开时不被 overflow 裁切，关闭后控制组恢复窄屏横向滚动。
- 分段控件激活项 hover 后仍保持当前强调色；所有 `.wb-compact-action` 次要/主要按钮的计算高度、圆角、边框、颜色、字重和内边距与共享组件一致。
- 列表分组筛选使用无底板的 `.wb-filter-segmented`，选中与 hover 均保持强调色弱底而非白色反白；`.wb-status-tag` 保持内容宽度、22px 高和双轴居中；`.wb-avatar` 的 SVG 在 22px 圆形强调色背景内以 14px 亮色图标居中。
- `.wb-flush-card` 的标题与正文必须是直接子项，正文桌面实际水平内边距为 20px、手机为 16px；不得因渲染包装层导致标题或正文计算内边距为 0。
